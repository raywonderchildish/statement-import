# Импорт банковской выписки — тестовое задание Mobile Engineer

Фрагмент мобильного приложения на React Native + TypeScript (Expo SDK 58, development build): выбрать синтетическую выписку, отправить её байты локальному mock API, дождаться результата, пережить потерю ответа и перезапуск, затем удалить импорт с подтверждением сервера.

| Папка | Что внутри |
|---|---|
| `mobile-engineer-kit/` | Набор из задания **без изменений** (первый коммит репозитория; `git diff <первый коммит> -- mobile-engineer-kit` пуст) |
| `app/` | Мобильный клиент и его тесты |
| `docs/` | [Результаты тестов](docs/TEST_RESULTS.md), [release note](docs/RELEASE_NOTE.md), [self-review](docs/SELF_REVIEW.md) |

|---|---|---|
| Android | Эмулятор Pixel 7, Android 16 (API 36), arm64 | **Проверено.** Выбор файла через системный picker и вся матрица приёмки пройдены, счётчики mock совпали с экраном (таблица ниже) |
| iOS | Симулятор iPhone 17, iOS 26.4.1, Xcode 26.4.1 | **Проверено.** Выбор файла через системный picker из «Файлов» и вся матрица приёмки пройдены, счётчики mock совпали с экраном (таблица ниже) |

### Матрица приёмки на Android

Сценарий mock переключался через `/__test/scenario`, счётчики читались из `/__test/state`.

| Сценарий | Что на экране | Счётчики mock после |
|---|---|---|
| happy, `statement.csv` | Отчёт: StreamBeam 19.99 AUD, BrightGrid 132.00 AUD, итого 151.99 AUD в месяц | `createRequests=1`, `newJobs=1`, `acceptedBytes=112`, SHA-256 задания равен SHA-256 файла |
| stale_status | После двух «Обновить статус» отчёт остаётся; в логе клиента `status_ignored`, `processing`, `revision 2`, `reason stale` | job `ready/3` |
| delete_failure | «Удалить не удалось. Данные импорта по-прежнему на сервере» | `deleteRequests=1`, job `ready/3` |
| happy, повтор удаления | «Удаление запрошено… данные ещё не удалены», затем «Сервер подтвердил: импорт удалён» | `deleteRequests=2`, job `deleted/5` |
| `spoofed.pdf` | «Это не PDF и не CSV-выписка» | `createRequests` не изменился (0) |
| `oversize.csv` | «Файл больше 10 МБ» | `createRequests` не изменился (0), приватных копий нет |
| lost_ack, `statement.pdf` | «Ответ сервера не получен. Импорт мог быть создан, а мог и нет» | `createRequests=1`, `newJobs=1` |
| lost_ack, затем `force-stop` и запуск | Отчёт показан без повторной отправки | `createRequests=1`, `newJobs=1`, `duplicateHits=0` |
| lost_ack, сервер недоступен, «Выйти без подтверждения» | Предупреждение, что импорт мог остаться на сервере; копии на устройстве нет | После возврата связи и перезапуска: `newJobs=1`, `deleteRequests=1`, job `deleted/5` |

Дополнительно на Android проверено: масштаб шрифта 2.0 на экране 720×1280 не ломает действия; в `logcat` за полный цикл импорта и удаления нет ключей идемпотентности и названий получателей. Имя файла в `logcat` встречается один раз — в строке системного `MediaProvider`, не приложения.

Дополнительно на iOS проверено:

- Самый крупный размер шрифта из настроек доступности (`accessibility-extra-extra-extra-large`): текст переносится, все кнопки достижимы прокруткой. Известный огрех: слово «Диагностика» на кнопке переносится посередине.

Найдено и исправлено при проверке iOS: система кладёт копию выбранного документа в `tmp/<bundle id>-Inbox` внутри песочницы приложения, и никто её не удаляет. Теперь клиент удаляет эту копию сразу после того, как сделал свою, и подчищает папку при запуске. После каждого сценария выше файлов в Inbox — 0, оригиналы в «Файлах» не затронуты.

## Запуск из чистого клона

Нужны Node.js 20+ (проверялось на 22.22.0), для Android — JDK 17 и Android SDK с эмулятором (переменные `JAVA_HOME` и `ANDROID_HOME` заданы, `adb` в `PATH`), для iOS — Xcode с симулятором и CocoaPods.

Что из этого раздела проверено в свежем клоне репозитория:

| Шаг | В свежем клоне |
|---|---|
| Mock: `npm run fixtures:oversize`, `npm test`, `npm start` | Проверено; набор в клоне побайтно совпадает с исходным архивом |
| Клиент: `npm ci`, `npm test`, `npm run typecheck` | Проверено |
| Android: команды ниже, затем вся матрица приёмки | Проверено |
| iOS: `npx expo run:ios`, команда для файлов в симуляторе, затем импорт `statement.csv` | Проверено: сборка с нуля прошла, приложение открылось само, импорт дошёл до отчёта, SHA-256 совпал, копий в песочнице нет. Остальные сценарии матрицы на iOS проходились на сборке из рабочей папки |

```bash
git clone https://github.com/raywonderchildish/statement-import.git && cd statement-import
```

### 1. Mock (терминал 1)

```bash
cd mobile-engineer-kit
npm run fixtures:oversize
npm start
```

Mock слушает `http://127.0.0.1:8787`. Установка пакетов не нужна.

### 2. Тесты клиента

Команды в шагах 2–4 выполняются из корня репозитория, каждая в своём терминале.

```bash
cd app
npm ci
npm test
npm run typecheck
```

Тесты сами поднимают mock из набора отдельным процессом на свободном порту с отдельным файлом состояния, поэтому не мешают mock из шага 1 и воспроизводимы. Перед каждым тестом вызывается `/__test/reset`. Ожидаемый результат: 3 набора, 41 тест — см. [docs/TEST_RESULTS.md](docs/TEST_RESULTS.md).

### 3. Android (терминал 2)

Запустите эмулятор, затем:

```bash
cd app
adb reverse tcp:8787 tcp:8787
adb push ../mobile-engineer-kit/fixtures/statement.csv /sdcard/Download/
adb push ../mobile-engineer-kit/fixtures/statement.pdf /sdcard/Download/
adb push ../mobile-engineer-kit/fixtures/spoofed.pdf /sdcard/Download/
adb push ../mobile-engineer-kit/fixtures/oversize.csv /sdcard/Download/
npx expo run:android
```

`expo run:android` сам генерирует папку `android/`, собирает debug-сборку, ставит её и запускает Metro. Первая сборка занимает 10–15 минут. Приложение откроется само. Чтобы открыть его заново после закрытия, повторите `npx expo run:android`: повторный запуск занимает около минуты.

### 4. iOS

```bash
cd app
npx expo run:ios
```

`expo run:ios` сам генерирует папку `ios/`, ставит зависимости CocoaPods, собирает и запускает приложение на симуляторе. Первая сборка скачивает около 400 МБ готовых библиотек. Симулятор обращается к `127.0.0.1` хоста напрямую, проброс портов не нужен.

Файлы набора нужно положить в «Файлы» симулятора, в раздел «На iPhone». Один раз откройте на симуляторе приложение «Файлы», затем выполните из корня репозитория:

```bash
BASE="$HOME/Library/Developer/CoreSimulator/Devices/$(xcrun simctl list devices booted | grep -oE '[0-9A-F-]{36}' | head -1)/data/Containers/Shared/AppGroup"
for d in "$BASE"/*/; do
  id=$(plutil -extract MCMMetadataIdentifier raw "$d.com.apple.mobile_container_manager.metadata.plist" 2>/dev/null)
  if [ "$id" = "group.com.apple.FileProvider.LocalStorage" ]; then
    mkdir -p "${d}File Provider Storage"
    cp mobile-engineer-kit/fixtures/statement.csv mobile-engineer-kit/fixtures/statement.pdf \
       mobile-engineer-kit/fixtures/spoofed.pdf mobile-engineer-kit/fixtures/oversize.csv "${d}File Provider Storage/"
  fi
done
```

В picker-е приложения файлы появятся во вкладке Browse → On My iPhone.

### Адрес mock

По умолчанию `http://127.0.0.1:8787`. Для физического устройства задайте адрес в локальной сети переменной `EXPO_PUBLIC_API_BASE_URL` при запуске Metro. В debug-сборке этого достаточно. В release-сборке Android HTTP без TLS разрешён только для `127.0.0.1`, `localhost` и `10.0.2.2`, поэтому новый хост пришлось бы добавить в `app/plugins/withLocalCleartext.js` и пересобрать приложение. Запуск на физическом устройстве не проверялся.

## Как пройти матрицу приёмки вручную

Сценарий переключается кнопками в панели «Диагностика mock» внизу экрана (она же показывает счётчики и обновляется раз в полторы секунды) или командой:

```bash
curl -X POST http://127.0.0.1:8787/__test/scenario -d '{"mode":"lost_ack"}'
```

```bash
curl http://127.0.0.1:8787/__test/state
```

| Сценарий | Шаги | Что проверить |
|---|---|---|
| happy | Выбрать `statement.csv` → Отправить | Сначала «ждёт в очереди / обрабатывается», затем отчёт на 151.99 AUD; `newJobs=1` |
| lost_ack | Включить `lost_ack` → выбрать файл → Отправить | Экран «исход неизвестен». Вариант А: «Проверить и повторить». Вариант Б: закрыть приложение и открыть снова. В обоих случаях `newJobs=1` |
| stale_status | При готовом отчёте включить `stale_status` → дважды «Обновить статус» | Отчёт не пропадает; в диагностике «проигнорирован: ревизия старее уже показанной» |
| delete_failure | Включить `delete_failure` → «Удалить импорт» | Сообщение, что данные по-прежнему на сервере. Включить `happy` → «Повторить удаление» → «Сервер подтвердил: импорт удалён» |
| spoofed + oversize | Запомнить `createRequests` → выбрать `spoofed.pdf`, затем `oversize.csv` | Оба отклонены, `createRequests` не изменился |

Между прогонами исходники менять не нужно; «Сбросить mock» в диагностике вызывает `/__test/reset`.

## Как устроено

- `app/src/import/` — ядро без зависимостей от React и нативных модулей. `engine.ts` держит инварианты:
  - ключ идемпотентности и запись об операции сохраняются **до** первого POST, ключ удаления — до первого DELETE; повторы используют их же;
  - после перезапуска выполняются только GET-запросы; повторный POST — только по кнопке, с тем же ключом и теми же байтами;
  - ответ сервера применяется, только если он относится к текущей операции, импорт ещё не `deleted` и ревизия не старее уже виденной;
  - `deleted` выставляется только из ответа сервера со `status=deleted`. Ответ 202 на DELETE означает `deleting`, 404 — «сервер не знает импорт»; ни то ни другое не показывается как удаление;
  - выход из «исход неизвестен» не выбрасывает ключ: он остаётся в списке отложенной уборки, пока сервер не ответит, что импорта нет или что он удалён.
- `app/src/platform/` — адаптеры устройства: системный picker, потоковая копия с лимитом, отправка тела запроса из файла нативным кодом, AsyncStorage.
- `app/src/ui/` — экран, панель диагностики, чистая функция «снимок состояния → экран» с тестами.

Проверка файла идёт по содержимому: PDF по сигнатуре `%PDF-`, CSV по заголовку (как в самом mock); расширение используется только для сверки. Размер проверяется по метаданным, а при копировании — потоком, с остановкой на 10 МиБ.

В логах и диагностике клиента допустимы только поля из белого списка (`app/src/import/logger.ts`): статус, ревизия, код ответа, формат, размер, идентификатор задания. Имя файла, байты, ключи и описания операций туда попасть не могут; это проверяется тестом.

## Известные ограничения

- На iOS система сама копирует выбранный документ в песочницу приложения целиком, до нашей проверки размера; повлиять на это через используемый picker нельзя. Клиент удаляет эту копию сразу после чтения. На Android такой копии нет.
- Адаптеры устройства (`app/src/platform/`) не покрыты автотестами: они работают только на устройстве и проверялись вручную на эмуляторе Android и симуляторе iOS.
- Одновременно поддерживается один импорт.
- Из состояния «исход неизвестен» можно выйти кнопкой «Выйти без подтверждения». Приложение сначала ещё раз спрашивает сервер; если импорт найден, выход отменяется и импорт удаляется обычным способом. Если нет — ключ сохраняется, и при следующих запусках приложение находит импорт по ключу и запрашивает его удаление. Подтверждение такого удаления пользователю не показывается, о чём сказано в предупреждении.
- При готовом отчёте закрыть импорт без удаления на сервере нельзя.
- Повреждённая запись об операции в хранилище считается отсутствующей: приложение покажет пустой экран, а импорт на сервере останется без ссылки на него. Восстановления для этого случая нет.
- Ответ «импорт неизвестен» (404) на запрос статуса окончателен: приложение не перепроверяет его позже, даже если 404 был временным.
- После сетевой ошибки при удалении экран говорит «данные по-прежнему на сервере», хотя сервер мог запрос принять. Это безопасная сторона ошибки; статус уточнится по кнопке «Обновить статус» или при повторе удаления.
- Отложенная уборка импортов, закрытых без подтверждения, запускается один раз при старте приложения.
- Панель диагностики mock есть только в отладочной сборке (`__DEV__`).
- Распознавание CSV повторяет правило mock (фиксированный заголовок) и для настоящих выписок слишком строгое.
