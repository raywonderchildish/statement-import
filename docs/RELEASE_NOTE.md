# Release note: импорт выписки

Факты ниже относятся к debug-сборкам, проверенным на эмуляторе Android 16 (API 36) и симуляторе iOS 26.4.1. На физических устройствах и в release-сборке фрагмент не запускался.

## Коротко

- **Разрешения:** на Android только `INTERNET`; на iOS системных запросов нет. Доступ к файлам даёт системный picker.
- **Копии файла:** одна приватная копия в кэше приложения, удаляется сразу после подтверждения импорта сервером, при отмене и при отклонении. Отчёт на диск не пишется.
- **Очистка данных:** «Удалить импорт» → подтверждение сервера → «Готово». После этого на устройстве нет ни копии, ни записи.
- **Стоп-сигналы rollout:** второй job на один ключ; «удалён» на клиенте при живом job на сервере; рост импортов, застрявших в «исход неизвестен».
- **Новый бинарник нужен** для разрешений, сетевой политики и любых нативных модулей; тексты, экраны и логика состояний — это JS.

Подробности по каждому пункту ниже.

## Разрешения

| Платформа | Что запрашивается | Зачем |
|---|---|---|
| Android | Только `INTERNET` | Запросы к API |
| iOS | Ничего, что показывает системный диалог в этом сценарии | — |

- Доступ к хранилищу не нужен: системный picker выдаёт приложению доступ на чтение к одному выбранному документу.
- Шаблонные `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, `SYSTEM_ALERT_WINDOW`, `VIBRATE` явно исключены из манифеста (`blockedPermissions` в `app.json`).
- В `Info.plist` debug-сборки есть `NSLocalNetworkUsageDescription` и `NSBonjourServices` — их добавляет `expo-dev-client` для поиска dev-сервера. В проекте Xcode есть шаг сборки «Strip Local Network Keys for Release», который убирает их из release-сборки; сама release-сборка не делалась, результат не проверялся.
- На симуляторе iOS за весь прогон матрицы системных диалогов о разрешениях не появлялось.

## Сеть

- HTTP без TLS нужен только из-за локального mock. Android: разрешён для `127.0.0.1`, `localhost`, `10.0.2.2`, для остальных хостов запрещён (`network_security_config`). iOS: в ATS включено только `NSAllowsLocalNetworking`.
- В debug-сборке Android политика мягче: HTTP без TLS разрешён для любого хоста. Это нужно dev-серверу Metro, который доступен по адресу компьютера в локальной сети; со строгой политикой отладочная сборка не загружалась. Файл с мягкой политикой лежит в debug-наборе ресурсов и в release-сборку не попадает. Release-сборка не делалась, это следует из устройства сборки Android, а не из проверки.
- В production-сборке с HTTPS-адресом оба исключения нужно убрать.

## Где остаются копии файла и данные

| Что | Где | Когда удаляется |
|---|---|---|
| Копия, которую делает iOS при выборе документа | `tmp/<bundle id>-Inbox/` в песочнице приложения | Клиентом сразу после создания собственной копии и при отклонении файла; оставшиеся после падения — при следующем запуске |
| Приватная копия выбранного файла | `cache/statement-import/<uuid>.tmp` в песочнице приложения | При отклонении файла, при «Отмена», сразу после подтверждения job сервером. Копии, оставшиеся после падения, удаляются при следующем запуске |
| Копия в состоянии «исход неизвестен» | Там же | Хранится, пока исход POST не выяснен: для повтора нужны те же байты |
| Запись об операции | AsyncStorage (на Android — база `RKStorage`) | По «Готово» после подтверждённого удаления или «Закрыть» после отказа |
| Ключи импортов, закрытых без подтверждения | AsyncStorage, отдельный список | Когда сервер ответил, что импорта нет или что он удалён |
| Отчёт (получатели, суммы) | Только в памяти процесса | При закрытии приложения; после запуска запрашивается заново |

- Запись об операции содержит: ключи идемпотентности, имя файла, размер, формат, `jobId`, статус и ревизию. Байтов файла и содержимого отчёта в ней нет (проверено чтением базы на эмуляторе).
- Picker настроен не делать собственную копию (`copyToCacheDirectory: false`). На Android это так и работает: после отклонения 10-мегабайтного файла каталог копий пуст.
- На iOS система всё равно копирует выбранный документ целиком в `tmp/<bundle id>-Inbox/`, какого бы размера он ни был; клиент не может этому помешать и удаляет копию сам. Проверено на симуляторе: после каждого сценария, включая отклонённые файлы, в Inbox 0 файлов, оригиналы в «Файлах» целы.
- Каталог кэша не входит в резервные копии. На Android дополнительно выставлено `allowBackup=false`, чтобы запись об операции не попадала в облачный бэкап. На iOS AsyncStorage в резервную копию устройства попадает; запись не содержит байтов, но содержит имя файла.
- Система может очистить кэш при нехватке места. Тогда повтор в состоянии «исход неизвестен» невозможен, и приложение прямо об этом говорит.

## Как очистить данные

1. В приложении: «Удалить импорт» → дождаться «Сервер подтвердил: импорт удалён» → «Готово». После этого на устройстве нет ни копии, ни записи.
2. Средствами системы: удалить приложение или очистить его данные. Это убирает только локальные данные; импорт на сервере останется.

## Логи и аналитика

- Аналитики в этом фрагменте нет. Диагностика пишется только в консоль разработчика в dev-сборке, в релизе отключена.
- В событие могут попасть только поля из белого списка: статус, ревизия, код ответа, причина, формат, размер, `jobId`. Имя файла, байты, ключи и описания операций исключены и типами, и проверкой во время выполнения.
- В `logcat` за полный цикл импорта и удаления ключей и названий получателей нет. Имя файла один раз записывает системный `MediaProvider` при открытии документа; приложение на это не влияет.
- В системном журнале симулятора iOS названий получателей и содержимого файла нет. Имя и путь выбранного документа пишут системные компоненты Apple, работающие в процессе приложения (`filecoordination`, `DocumentManager`); код приложения имён не пишет. Как эти строки выглядят на физическом устройстве, не проверялось.

## Сигналы для остановки rollout

Событий в аналитику фрагмент пока не шлёт; ниже — что нужно подключить и на что смотреть. Все события уже есть в логгере.

| Сигнал | Событие | Почему останавливает |
|---|---|---|
| Больше одного job на один ключ (на сервере) | — | Нарушена идемпотентность: стоп-фактор |
| «Удалён» на клиенте при job, существующем на сервере | `delete_confirmed` против серверных данных | Ложное подтверждение удаления: стоп-фактор |
| Рост доли импортов, оставшихся в «исход неизвестен» | `create_uncertain` без последующего `job_confirmed` | Восстановление по ключу не работает |
| Рост `job_missing` | `job_missing` | Сервер теряет задания или клиент хранит чужие идентификаторы |
| Рост неуспешных удалений без повтора | `delete_failed` | Данные пользователей не удаляются |
| Импорты, закрытые без подтверждения и не убранные | `import_abandoned` без `abandoned_cleanup` со значением `settled` | На сервере остаются данные, о которых пользователь не знает |
| Рост отклонений `unreadable` на одной платформе | `file_rejected` | Сломан доступ к документам у провайдера или версии ОС |
| Падения в picker или при копировании | crash-отчёты | Нативная часть |

## Что требует нового бинарника, а что можно доставить по OTA

OTA-обновления в проекте не подключены (`expo-updates` не установлен). Граница на случай подключения:

| Изменение | Доставка |
|---|---|
| Тексты, экраны, логика состояний, правила проверки файла, интервалы опроса | JS, можно OTA |
| Адрес API (`EXPO_PUBLIC_API_BASE_URL` встраивается в JS-бандл) | JS, но на Android новый HTTP-хост должен быть в `network_security_config` — это бинарник |
| Список хостов с HTTP без TLS, ATS | Бинарник |
| Разрешения, `allowBackup`, идентификатор приложения | Бинарник |
| Любой нативный модуль: picker, файловая система, AsyncStorage, crypto, safe-area | Бинарник |
| Обновление Expo SDK или React Native | Бинарник |

OTA-обновление, которое ожидает нативный модуль, отсутствующий в установленном бинарнике, упадёт при запуске; версии JS и бинарника должны быть связаны через runtime version.
