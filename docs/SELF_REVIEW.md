# Self-review

## Три решения

**1. Сначала запись, потом запрос.** Ключ идемпотентности и запись об операции сохраняются до первого POST, ключ удаления — до первого DELETE. После перезапуска приложение делает только GET по ключу; повторный POST возможен только по кнопке, с тем же ключом и теми же байтами. Цена: приватная копия файла хранится, пока исход POST неизвестен.

**2. Ответ сервера применяется, только если он не «чужой» и не старее виденного.** Три проверки в одном месте: ответ относится к текущей операции, импорт ещё не `deleted`, ревизия не меньше сохранённой. Это закрывает `stale_status` и поздний ответ после удаления. `deleted` выставляется только из ответа сервера: 202 на DELETE означает «удаляется», 404 — «сервер не знает импорт».

**3. Своя копия файла с лимитом.** Приложение читает документ потоком по 256 КБ в приватный каталог кэша и останавливается на 10 МиБ; формат определяется по первым байтам. Большой файл не попадает в память целиком, после отклонения следов не остаётся.

## Что упрощено ради срока

- Один импорт одновременно.
- Опрос статуса с фиксированным интервалом 700 мс, без backoff.
- Выход из «исход неизвестен» удаляет серверный импорт позже и без подтверждения пользователю; уборка идёт один раз при запуске.
- Распознавание CSV повторяет строгое правило mock (фиксированный заголовок).
- Адаптеры устройства не покрыты автотестами; матрица на устройстве проходилась вручную.
- Только эмулятор Android и симулятор iOS, без физических устройств и release-сборок.

## Что сломается первым в production и как это заметить

- **Повтор после потери ответа**, если система очистила кэш и копии файла нет. Сигнал: импорты с кодом `copy_missing` и доля импортов, не дошедших до `job_confirmed`.
- **Импорт остался на сервере после «Выйти без подтверждения»**, если пользователь больше не открыл приложение. Сигнал: `import_abandoned` без последующего `abandoned_cleanup` со значением `settled`.
- **Копия документа в `tmp/…-Inbox` на iOS**, если новая версия iOS поменяет место системной копии. Сигнал: рост занятого места в песочнице; проверка содержимого `tmp` на каждой новой версии iOS.

## Использование AI и моя роль

При выполнении задания я использовал AI-ассистент Claude Code (Anthropic). Примерное соотношение: 80% работы выполнено с помощью AI, 20% самостоятельно.

**AI (около 80%)** помогал с генерацией основной части кода, шаблонного кода, компонентов, обработчиков и тестов, с рефакторингом, а также собирал приложение и прогонял сценарии на эмуляторе и симуляторе.

**Я (около 20%)** самостоятельно проработал требования и критерии оценки, спроектировал архитектуру и структуру приложения и определил подходы к реализации. Три ключевых решения были заданы до начала кодирования. Работу я разбил на шесть этапов в порядке весов из критериев. Я проверял результаты AI, проводил code review, тестировал функциональность и отвечал за финальное качество. Там, где были варианты, выбирал я: например, оставить выход из «исход неизвестен», хотя он усложняет код, и не считать iOS проверенным по одной обязательной матрице.

**Как проверялся результат AI.** Помимо тестов было два независимых шага.

- Код прочитал второй экземпляр AI без доступа к истории разработки, с задачей найти путь к любому из трёх стоп-факторов. Таких путей он не нашёл, но нашёл семь ошибок на краях; шесть исправлены и покрыты тестами, остальное — в известных ограничениях README.
- Проект развёрнут из свежего клона по README на обеих платформах. Это нашло ошибку, которую не ловили тесты: приложение не открывалось на Android, потому что сетевая политика блокировала dev-сервер.

Утечку системной копии файла в `tmp/…-Inbox` на iOS нашёл AI при прогоне на симуляторе.
